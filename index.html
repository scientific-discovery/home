Building safe LLM agents for open-ended scientific discovery

Language models can propose hypotheses far faster than any lab can test them. We build agents that ground every proposal in domain knowledge, test it against real evidence, and run the next experiment when the data cannot yet tell competing hypotheses apart.

Central theme

Safety has to be built into the discovery loop

Open-ended discovery has no answer key to check against, and language models fail quietly. They can fit the data with a law that has the wrong mechanism, propose a material that cannot be made, or repeat a known result as if it were new. Our agents are built to catch these failures inside the loop, before anything is reported as a discovery.

  1. 01

    Propose within constraints

    The LLM drafts hypotheses as equations, programs or crystal structures, inside a search space shaped by domain rules and priors.

    • LLM-ACESoperator priors
    • AutoSciLabcompeting mechanisms
    • LLEMAchemistry-informed rules
    • LLM-FEdomain-aware programs

  2. 02

    Test against evidence

    Every proposal is executed, fitted and scored on data, simulators or property oracles. Nothing is accepted on the model’s word.

    • LLM-ACESfit and score each ODE
    • AutoSciLabrefit on every new result
    • LLEMAsurrogate property oracle
    • LLM-FEvalidation score of a model

  3. 03

    Choose the next experiment

    The agent queries where its competing hypotheses disagree most, so each new observation rules something out.

    • LLM-ACESinitial conditions of maximum divergence
    • AutoSciLabqueries of maximum disagreement

  4. 04

    Remember and calibrate

    Successes, failures and confidence checks are written back to memory, steering later rounds away from spurious fits and memorized answers.

    • LLM-ACESbest and worst equations
    • AutoSciLabbootstrap confidence gate
    • LLEMAreward and error memories
    • LLM-FEisland-based program memory

How the projects connectLLM-FE and LLEMA run steps 01, 02 and 04 as an evolutionary search. LLM-ACES and LLM-AutoSciLab add step 03, so the agent also decides which experiment to run next.

NeurIPS 2026Dynamical systems

LLM-ACES

Closed-Loop Discovery of Dynamical Systems with LLM-Guided Adaptive Search

Recovers the differential equations behind a dynamical system. An LLM proposes operator priors, candidate equations are fit within each, and their disagreement picks which initial conditions to simulate next. It has the lowest median error across 122 ODE systems and beats baselines with a tenth of the data.

Recovered exactly · Schnackenberg system

ẋ0 = 0.24 + x02x1 − x0

ẋ1 = 1.43 − x02x1

Nikhil Abhyankar*, Sha Li*, Sanchit Kabra*, Naren Ramakrishnan, Yulia Gel, Chandan K. Reddy

NeurIPS 2026Physics · Chemistry · Biology

LLM-AutoSciLab

Closed-Loop Scientific Discovery via Active Experimentation with LLMs

Runs discovery as a loop of hypotheses and experiments. The agent proposes competing mechanisms, tests them where they disagree most, and keeps only what survives the evidence. It introduces ActiveSciBench for enzyme kinetics and gene networks, and is 2–5× more sample-efficient than the strongest baselines.

Recovered law vs. ground truth

truew = k/m1.30 − (b/2m)0.70

foundw = k/m1.30 − (0.4915 b/m)0.69

Sanchit Kabra*, Nikhil Abhyankar*, Saaketh Desai, Prasad P. Iyer, Chandan K. Reddy

ICLR 2026Materials science

LLEMA

Evolutionary Search with LLMs for Multi-Objective Materials Discovery

Designs crystalline materials that must meet several property targets at once. An LLM proposes candidates under chemistry-informed rules, surrogate models predict their properties, and success and failure memories guide the next generation. Across 14 real-world tasks it reaches higher hit-rates than generative and LLM-only baselines.

Proposed for high-k dielectrics

ZrAl2O5·Hf0.5Zr0.5O2

Close to Zr–Al and Hf–Zr oxides that experts study for high-k gates.

Nikhil Abhyankar*, Sanchit Kabra*, Saaketh Desai, Chandan K. Reddy

TMLR 2026Tabular machine learning

LLM-FE

Automated Feature Engineering for Tabular Data with LLMs as Evolutionary Optimizers

Treats feature engineering as program search. The LLM writes feature transformations as Python code, each program is scored by training a model on its output, and the best programs seed the next round. It outperforms AutoFeat, OpenFE and earlier LLM methods on 26 datasets.

Example feature program

# insulin resistance is a known diabetes risk factor
df_out["insulin_resistance"] = df_in["glucose"] * df_in["insulin"] / 405

Nikhil Abhyankar, Parshin Shojaee, Chandan K. Reddy
