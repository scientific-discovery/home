Building Safe LLM Agents for Open-Ended Scientific Discovery

Language models can propose hypotheses far faster than any lab can test them. We build agents that ground every proposal in domain knowledge, test it against real evidence, and run the next experiment when the data cannot yet tell competing hypotheses apart.

The Discovery Loop

All four projects follow the same loop. An LLM proposes hypotheses within domain constraints, each one is tested against evidence, and the results are written back to memory for the next round. LLM-FE and LLEMA run steps 01, 02 and 04 as an evolutionary search. LLM-ACES and LLM-AutoSciLab add step 03, so the agent also chooses which experiment to run next.

  1. 01

    Propose within constraints

    The LLM drafts hypotheses as equations, programs or crystal structures, inside a search space shaped by domain rules and priors.

    • LLM-ACESoperator priors
    • AutoSciLabcompeting mechanisms
    • LLEMAchemistry-informed rules
    • LLM-FEdomain-aware programs

  2. 02

    Test against evidence

    Every proposal is executed, fitted and scored on data, simulators or property oracles. Nothing is accepted on the model’s word.

    • LLM-ACESfit and score each ODE
    • AutoSciLabrefit on every new result
    • LLEMAsurrogate property oracle
    • LLM-FEvalidation score of a model

  3. 03

    Choose the next experiment

    The agent queries where its competing hypotheses disagree most, so each new observation rules something out.

    • LLM-ACESinitial conditions of maximum divergence
    • AutoSciLabqueries of maximum disagreement

  4. 04

    Remember and calibrate

    Successes, failures and confidence checks are written back to memory, steering later rounds away from spurious fits and memorized answers.

    • LLM-ACESbest and worst equations
    • AutoSciLabbootstrap confidence gate
    • LLEMAreward and error memories
    • LLM-FEisland-based program memory

About

Nikhil Abhyankar

PhD, CS at Virginia Tech

Nikhil works on making LLM-based systems reliable enough for decision-making over structured data and scientific workflows. His research sits where LLM reasoning, tabular data and AI for science meet, with a focus on methods and benchmarks that expose real failure modes and improve end-to-end performance.
